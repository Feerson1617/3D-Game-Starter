# Technische Abschlussprüfung – 18. Oktober 2026

Änderungen ausschließlich auf `codex/audit-template-reliability` in [Pull Request #1](https://github.com/Feerson1617/3D-Game-Starter/pull/1). Kein Merge. Andere Spiele und Repositorys wurden nicht bearbeitet.

## Ergebnis

Three.js, modulares JavaScript und Vite sind eine geeignete kostenlose Ausgangsbasis für hochwertige Browser-3D-Projekte. Eine Neuimplementierung oder ein Rendererwechsel ist nicht erforderlich. Fotorealismus bleibt das langfristige Ziel; die Testszene erreicht ihn noch nicht. Die Vorlage ist ein erweiterbarer Einstieg, keine bereits vollständige Engine für beliebig große Spielwelten.

Das Repository ist bereits öffentlich und als **Template repository** markiert. Die vom Nutzer bestätigte Hauptveröffentlichung wurde nicht neu eingerichtet. Für neue Repositorys weiterhin **Settings → Pages → Source: GitHub Actions** aktivieren, Actions gegebenenfalls freigeben und einmal den Pages-Workflow starten. Der neue Repositoryname muss nicht im Quellcode eingetragen werden. Die aktualisierte Codex-Cloud-Anleitung steht in [SETUP](SETUP.md).

## Echte GitHub-Vorschau: noch keine öffentliche Freigabe

Branch und PR #1 lösen den Build und nachfolgenden Pages-Workflow tatsächlich automatisch aus. **Die öffentliche PR-Vorschau ist vor dem Merge noch nicht funktionsfähig.** Der Browser erhielt unter `/3D-Game-Starter/pr-preview/pr-1/` HTTP 404, obwohl die Actions grün waren.

Im [Publisher-Lauf 39147388397](https://github.com/Feerson1617/3D-Game-Starter/actions/runs/39147388397) steht `PR #1: unavailable or invalid preview: HTTP Error 401`. Der bestehende Downloader gibt den GitHub-Authorization-Header an den signierten Speicherhost weiter. Die Korrektur entfernt ihn bei Hostwechseln.

Der [PR-Lauf 39147620693](https://github.com/Feerson1617/3D-Game-Starter/actions/runs/39147620693) hat den korrigierten Download **mit einem echten Artefakt auf GitHub erfolgreich verifiziert**: `Validated real artifact 12143569386 for PR #1 at 48fe169881a066762279f82b4a29c19d949b895c`. Der Test besitzt nur `contents: read` und `actions: read` und kontrolliert außerdem sicheres Entpacken und die PR-/Commit-Zuordnung.

Der privilegierte Publisher führt absichtlich nur freigegebenen Code von `main` aus. Deshalb verwendet er die Korrektur im offenen PR noch nicht. Der abschließende öffentliche Erfolg ist **erst nach deiner ausdrücklichen Merge-Freigabe** prüfbar. Kein Sicherheitsmechanismus wurde umgangen; kein PR-Code wurde mit zusätzlichen Schreibrechten ausgeführt.

Nach deiner Prüfung und einem von dir freigegebenen Merge den Pages-Lauf abwarten und beim nächsten offenen PR dessen Vorschau im Browser öffnen. PR #1 selbst wird beim Merge geschlossen und seine Vorschau entfernt. Keine zusätzliche kostenpflichtige Funktion oder Änderung der funktionierenden Pages-Einstellung erforderlich.

## Verbleibende Grenzen

- Kein Test auf physischem Schul-iPad. WebKit/Touch-Emulation ersetzen keine Prüfung von Bildrate, Erwärmung und Speicher auf dem ältesten eingesetzten Gerät. Der Safari-Seitencache wurde per Lifecycle-Ereignis simuliert.
- Keine großen fotorealistischen Assets, Skelettanimationen, HDR-Umgebungen oder Draco-/Meshopt-/KTX2-Decoder getestet. Hochwertige lizenzierte Assets und lokale Decoder später projektspezifisch ergänzen.
- Große Welten benötigen Budgets, LOD, Instancing und Streaming. Wissenschaftliche Simulation, Physik, Spielzustände und umfangreiche Spielstände sind projektspezifisch aufzubauen. Das aktuelle Speicherschema enthält Anzeige und Kamera.
- HDR-Umgebungsreflexionen fehlen noch. PBR, ACES und Schatten ermöglichen den Ausbau; aktuelle Grafik bleibt eine technische Demo.
- Antialiasing wird bei Renderer-Erstellung festgelegt; laufende Qualitätswahl verändert Auflösung und Schatten. Vite meldet eine Größenwarnung für das Three.js-Hauptbündel (rund 581 kB, rund 149 kB gzip); der Build besteht.
- Bestehende Vorschaugrenzen: maximal zwölf interne PRs, letzte 100 Buildläufe, Artefakte nach sieben Tagen ablaufend, keine Fork-Vorschauen, öffentliche gemeinsame Origin. Eigene Domains werden in der Kommentar-URL nicht automatisch erkannt.
- Gleichzeitige öffentliche Veröffentlichung mehrerer PRs und öffentliche Entfernung beim Schließen wurden nicht zusätzlich live ausgelöst; Zusammenstellung und Bereinigung sind lokal geprüft.
- GitHub weist auf ältere Node-Runtimes einzelner bestehender offizieller Actions hin und führt sie kompatibel aus. Ihre Versionen bei späterer Wartung gezielt aktualisieren; kein pauschaler Ersatz funktionierender Workflows.
